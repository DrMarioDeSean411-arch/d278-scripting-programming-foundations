## What Is This?

A practice exam built around the three D278 competencies and the question patterns used in the four official D278 practice tests: troubleshooting and debugging, abstraction and objects, data types and naming, expressions and operator precedence, functions, branches, loops, arrays, searching, runtime and space, heuristics, and NP-complete problems. ### The simulation

The real D278 exam gives you 70 questions in mixed order with no hint about which competency each one tests. The simulation does the same:

- 23 questions from C1, 29 from C2, and 18 from C3, the same proportions as the official practice tests
- A 120-minute countdown that submits automatically at zero
- No feedback until you submit. You can change answers and flag questions before then.
- A results screen with your score, your score per competency, and a review of every question you missed
- Every attempt draws a new random set, so a retake is not the same exam. Some questions you saw in the practice sections may appear.

### The study tools

These sit under the "Study tools" label and do not count toward any score.

- **Trace Lab.** Runs course-style pseudocode one line at a time. A variable table shows every value, with changed values highlighted, and an output panel shows what has been printed. Step forward and back, drag the slider, or press Play. Pick one of 24 programs, paste your own, and change the input values. Programs that fail on purpose (a missing return value, an index out of range, a loop that never ends) show the error in plain words. After you answer a question that contains runnable code, an **Open in Trace Lab** button loads that code with the input values from the question. Fill-in questions with XXX and YYY placeholders are not runnable, so they do not get the button.
- **Study Guide.** One card for each group of related topics, written in the course's pseudocode style, with key points, common traps, and buttons that jump to practice questions or a matching Trace Lab program. After you answer any question, **Review this concept** opens the right card, and **Back to your question** returns you to the same place.
- **Search Lab.** Shows linear and binary search stepping through a list you choose, counting comparisons. It includes an unsorted-list example where binary search misses a value that is present, and a table showing how the worst case grows from 8 elements to a billion.

During a running simulation the practice sections and study tools are locked, so a timed attempt cannot be helped along. They unlock when you submit.

## How to Use This Exam

1. Work through C1, C2, and C3. Trace every code question by hand on paper before you click an answer.
2. Read the rationale and the instructor note on every question, including the ones you got right.
3. When you miss a code question, press **Open in Trace Lab** and step through it until you can say which line produced the wrong value. When you miss a concept question, press **Review this concept**.
4. Watch the breakdown bars under each section. Any topic below 80% needs more study.
5. When all three sections are above 80%, take the timed simulation under real conditions: no notes, no pausing.

## Topics Covered

**C1 — Identify Scripts and Program Requirements**
Bits, bytes, and binary · embedded computers and Moore's Law · compilers and interpreters · statically and dynamically typed languages · libraries · abstraction · classes, objects, and abstract data types · debugging by inspection and output statements · troubleshooting (problem, hypothesis, test, solution, ordering hypotheses, sub-hypotheses, binary-search troubleshooting) · identifiers and comments · data types · constants · variables and expressions

**C2 — Use Fundamental Programming Elements**
Operator precedence · integer and floating-point division · the modulo operator · assignment and swapping values · floating-point comparison · function definitions, calls, parameters, arguments, return values, stubs, and nested calls · random numbers and seeding · if / elseif / else and independent if statements · nested branches · boundary conditions and logical operators · while and for loops, sentinels, counters, and nested loops · arrays, indexes, sizes, and out-of-range errors · output and newlines

**C3 — Explain Logic and Outcome of Simple Algorithms**
Algorithm definition, inputs, and outputs · ordering algorithm steps · finding a maximum or minimum · linear search and binary search (preconditions, traces, and runtime) · best, worst, and average cases · space complexity · efficiency tradeoffs · sorting and swaps · heuristics · NP-complete problems · tracing loop-based algorithms
